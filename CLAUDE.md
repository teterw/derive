# Derive — working conventions

Read `PROMPT.md` (the build spec) and `docs/CURRICULUM.md` before changing
content. `docs/CONTENT-PIPELINE.md` governs how questions get added.
`PROGRESS.md` records where the build is and what comes next.

## Commands

| | |
|---|---|
| `pnpm dev` | dev server |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm lint` | eslint (flat config) |
| `pnpm test` | vitest, run once |
| `pnpm db:generate` | write a new SQL migration from the schema |
| `pnpm db:migrate` | apply `drizzle/*.sql` to `DATABASE_URL` |
| `pnpm db:push` | shove the schema straight at the database (dev only) |
| `pnpm db:seed:admin` | create/promote the bootstrap admin from `.env` |
| `pnpm content:coverage` | per-skill gaps: generators, difficulties, lesson, shapes |
| `pnpm smoke` | the whole stack against the real database, then cleans up |
| `pnpm render-check` | fetch every page as a signed-in user and look at it |
| `pnpm db:seed:demo` | a demo account with history (`-- --clean` to remove) |

Scripts read `.env` then `.env.local`, with `.env.local` winning.

**Compiling is not rendering.** `pnpm build` passing has twice hidden a bug
that `pnpm render-check` found in seconds. Run it after touching routing,
translations or anything a server component reads.

pnpm is installed per-user (`npm i -g pnpm`), not via corepack. On this machine
pnpm resolves from PowerShell, not Git Bash.

## Next.js 16 specifics

- **`proxy.ts`, not `middleware.ts`.** Renamed in 16; the exported function is
  `proxy`, and the runtime is `nodejs` and cannot be changed.
- `params`, `searchParams`, `cookies()` and `headers()` are all **async**.
- Route prop types (`PageProps<"/[locale]/login">`, `LayoutProps<"/[locale]">`)
  are generated. After adding or moving a route, run `pnpm exec next typegen`
  or the types will be stale and `tsc` will complain about routes that exist.
- Turbopack is the default bundler for both `dev` and `build`.

## Auth

- `proxy.ts` is an **optimistic** gate: cookie present or not, nothing more.
  Authorisation is `requireUser()` / `requireAdmin()` inside the page or the
  action. Never trust a `user_id` that arrived from the client.
- Sessions: 32 random bytes in the cookie, SHA-256 in the database, sliding
  refresh past the halfway mark, 30 days with "remember me" and 12 hours
  without.
- Passwords are argon2id via `@node-rs/argon2`. `Algorithm` is an ambient
  `const enum`, which `isolatedModules` forbids reading, so `lib/auth/password.ts`
  uses the literal `2` with a comment.
- Rate limiting is a database table (`auth_failures`), not an in-memory map,
  because every Vercel invocation is a fresh process.

## Database

- Neon **WebSocket** driver (`drizzle-orm/neon-serverless`), not the HTTP one:
  registration needs a real transaction and `neon-http` has none.
- `lib/db/index.ts` exports `db` as a lazy Proxy. `next build` imports every
  route module, so connecting eagerly would make builds require a live
  database.
- `users.username` is plain lower-cased `text`, not `citext`: creating the
  extension is not something `drizzle-kit push` can do. `normalizeUsername()`
  is the only thing that writes the column.
- Content ids (`topicId`, `skillId`, `generatorId`, `RuleId`) are strings in
  the database and live in `content/` in code. Never renumber one.

## i18n

- `th` is the default locale and the source of truth for terminology. English
  is the translation.
- Every user-visible string goes in `messages/{th,en}.json`. Server actions
  return an error **key** (`"inviteExhausted"`), never a sentence.
- `messages/th.json` and `messages/en.json` must have identical key sets.

## Styling

- Tailwind v4, configured in `app/globals.css` — there is no `tailwind.config`.
- Colours are CSS variables mapped through `@theme inline`: `bg-surface`,
  `text-muted`, `border-border`, `text-accent`, `text-correct`, `text-wrong`.
- Dark mode is `prefers-color-scheme` plus a `.dark` / `.light` class override,
  applied before paint by an inline script in the locale layout.
- `components/ui/` holds small shadcn-style primitives written by hand (cva +
  `cn`), not generated by the shadcn CLI.

## Content

- A generator works **backwards from the answer**; a derivation that was not
  constructed cannot be trusted. `content/generators/property.ts` is the §9
  gate every generator runs through, and it is not optional.
- Steps carry `math` (the mathjs form, zero form for equations) and `chain`.
  Adjacent steps in a chain must be equivalent - that is what the gate checks.
- Lesson worked examples are `(generatorId, seed, difficulty)` triples, never
  hand-written, so a lesson page cannot show unverified working.
- Prose with maths in it is segmented at render time by
  `components/math/math-text.tsx`. Write ordinary sentences; use `$...$` only
  when the guess would be wrong.

## Statistics

- Every aggregate is SQL over `attempts` / `daily_stats`. Raw rows are never
  shipped to the browser to be summed there.
- A "day" is an Asia/Bangkok calendar day, computed when the attempt row is
  written and stored on it. Never derive a day from a UTC timestamp at read
  time.
- Times a learner reads are Asia/Bangkok too - `bangkokStamp()`, not
  `toISOString()`.
- Chart colours come from the validated `--viz-*` ramp in `globals.css`. If you
  add a chart, run the data-viz validator against both surfaces rather than
  picking colours by eye.

## Writing files with backslashes in them

Most content here is KaTeX, which is backslashes all the way down. Two traps,
both of which have bitten:

- A shell heredoc in this environment collapses `\` to ``. Write files
  containing LaTeX with the editor tools or a node script, never a heredoc.
- In a template literal, a mis-escaped command does not leave a broken
  backslash behind - it eats it. `\left` written with one backslash becomes
  the word `left`; `\times` becomes a tab. Neither leaves anything for a
  "raw command in prose" check to find, which is why
  `components/math/math-text.test.ts` also looks for command names that have
  lost their backslash.
